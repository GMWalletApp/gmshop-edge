# 菲区快速补货自动分批

根因：菲区凭证导入每批最多 5 张，页面却整批提交，并隐藏具体错误。
最小修复：浏览器按每批 5 张顺序调用现有补货接口，每次总量最多 100 张；
每批完成凭证校验和商城卡码入库后再继续。不并发调用、不新增长时服务端任务，
其他 SKU 路由保持不变。

弹窗和页面显示已确认的批次、凭证入库数、商城新增数。网络结果不明、凭证被
拒绝/隔离或商城生成失败时立即停止，禁止自动重试。失败批次可能部分落库，
必须先核对库存再恢复。既有凭证去重、商城指纹和请求单号机制保持不变；重复
提交已经入库的凭证不会新增商城卡码。

集成测试同时发现 D1 的 meta.changes 包含触发器写入，不能当作商城新增数。
改为按本批生成的全新行 ID 回读实际库存行，不把计数器、审计和回执计入补货量。

验证包含：30 张拆 6 批、尾批、空行、顺序处理、部分失败停止、不确定结果不
重试、重复凭证、总量上限、其他路由不变；真实补货服务函数在空库迁移后新增
30 行，再提交同批凭证新增 0 行。浏览器验收、部署与本地测试结果分别报告。

消融：未引入队列、表结构、依赖、新服务端批处理接口或自动恢复机制。未采购、
发送邮件、修改生产库存，也未部署。

本地补货、权限、前端边界、查询计划和队列相关 54 项测试通过，双端构建与类型检查通过。
浏览器以模拟接口完成中文桌面和英文深色移动端流程，未执行生产写入。

菲区批次之间等待 3.3 秒，兼容校验接口共享的 3.1 秒冷却窗口。仓库只处理批内间隔，
因此不能省略批间等待；新增虚拟时钟测试验证间隔到期前不会发送下一批。
